Fixed Bugs

Bug #1: Whitespace-only subject lines accepted as valid input

Location: supabase/functions/optimize-subject/logic.ts:8

Description: The buildPrompt function accepted whitespace-only strings (e.g., " ", "\t\n") as valid subject lines because the check !originalSubject only catches empty strings, null, and undefined. Whitespace-only strings are truthy in JavaScript, so they passed validation but would produce prompts with effectively empty subjects.

Test: supabase/functions/optimize-subject/logic_test.ts - "buildPrompt throws when originalSubject is whitespace-only"

Fix: Added !originalSubject.trim() to the validation check to reject whitespace-only input.

Bug #2: Negative Unix timestamps incorrectly rejected

Location: supabase/functions/check-subscription/logic.ts:9, supabase/functions/stripe-webhook/logic.ts:25

Description: The toIsoFromUnixSeconds function used unixSeconds <= 0 to reject invalid timestamps. However, negative timestamps are valid and represent dates before January 1, 1970 (Unix epoch). While rare for subscription dates, this could cause issues with historical data or test fixtures using pre-1970 dates.

Test: supabase/functions/check-subscription/logic_test.ts - "toIsoFromUnixSeconds handles negative timestamps (pre-1970 dates)"

Test: supabase/functions/stripe-webhook/logic_test.ts - "toIsoFromUnixSeconds handles negative timestamps (pre-1970 dates)"

Fix: Changed validation to explicitly check for null, undefined, and exactly 0 (which is ambiguous), while allowing negative timestamps to be converted correctly.

Bug #3: Open Redirect vulnerability in customer-portal buildReturnUrl

Location: supabase/functions/customer-portal/logic.ts:9

Description: The buildReturnUrl function accepted any URL matching ^https?:// regex, including malicious external URLs like http://evil.com. An attacker who could control the Origin header could redirect users to a phishing site after they complete billing portal actions. This is a classic Open Redirect vulnerability (OWASP A01:2021).

Test: supabase/functions/customer-portal/logic_test.ts - "buildReturnUrl rejects non-localhost external origins to prevent open redirect"

Fix: Added an allowlist of trusted origin patterns (localhost, 127.0.0.1, subjectai.com, subject-ai*.vercel.app) and only use origins that match. Unknown origins fallback to localhost:3000.

Bug #4: Unhandled JSON parsing exception in optimize-subject

Location: supabase/functions/optimize-subject/index.ts:25

Description: The req.json() call was not wrapped in try/catch, meaning malformed JSON in the request body would throw an unhandled exception and crash the function with an unhelpful error. Compare to create-checkout which uses .catch() for graceful handling.

Test: supabase/functions/optimize-subject/logic_test.ts - "parseRequestBody returns default values for malformed JSON"

Fix: Added parseRequestBody() helper function that safely parses JSON and returns defaults on failure. Updated index.ts to use req.text() + parseRequestBody() for graceful handling.
